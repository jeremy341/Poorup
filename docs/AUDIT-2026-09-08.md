## 1. Verified findings worth fixing

### Server logic
- **[V] Counter/negotiate bypasses table obligations** — `server/contractLogic.js` counter/adjust paths use `contractProposalRejectionWithoutTurn`, which omits the `tableObligationOpen` check that `proposePlayerContract` enforces. A counter can land during `pendingPayment`/auction/purchase-offer. Low severity (same two parties renegotiating their own pending deal) but breaks the mutual-exclusion invariant.
- **[V] Disconnected bots act, including bankruptcy** — `server/botApi.js:108-126` `botActionRejection` checks only `isBot`, and `actAsBotSocket` swaps `socketId` so liveness checks pass; `server/bankruptcyLogic.js:62-67` `bankruptcyRefusal` omits `disconnected`. A disconnected bot seat can act and can declare bankruptcy. Human path is safe only because the socket mapping is deleted.
- **[V] Build/sell skips cross-obligation gates (nuanced)** — `server/propertyApi.js` `buildSellRejection` enforces own-debt + your-turn + pre-roll only. Building mid-auction or mid-trade is allowed. Low severity: the turn gate exists, and spending cash pre-bid is arguably strategy — but flagging because mortgage legs got the full 6-obligation gate while the stronger action (cash↔houses conversion) did not.

### Finance UI (all [V])
- **Bank `<details>` forgets open state** — rail rebuilds `innerHTML` on every render with no `open` memory, so an opened bank section collapses on any chat/turn re-render. Real annoyance, small fix (persist flag or move bank out of the re-rendered subtree).
- **NEEDS YOU count misses trades** — `financeHeaderHTML` counts offer + due debts only, but incoming trades render in their own TRADE block. Awaiting-my-response trades never increment N. (Outgoing correctly excluded from M LIVE — that's label-correct, not a bug.) Fix should count only responder-side trades (`toPlayerId === me`), not ones I proposed.
- **Property picker wrong-tile preview** — selecting NO ELIGIBLE DEEDS stores `Number("") = 0`; `financingPreviewTile` falls back to `deeds[0] || TILES[21]`, so the preview shows an unrelated tile while the picker says none eligible. SEND is gated off in this state (per `financingSendBlocked`), so cosmetic-only, but the preview lies.
- **Offer popup has no Decline** — `clientGameModalsUi.js` offer modal is Accept/Negotiate only; scrim/Escape just closes. Decline exists only via the deal view (`clientDealUi.js:96`). A dismissed offer sits pending server-side (single-slot: blocks all future trades until accepted/declined/expired). Medium UX gap.
- **Home alias form has no submit button** (`public/index.html:173-177`) — label + input + error only; submit works via Enter (`onHomeAliasSubmit` exists). Mouse-only users see no affordance. Minor.

### Input/accessibility (all [V])
- **Face canvas is mouse-only** — `clientProfileBindings.js:353` binds `mousedown/mouseover/mouseup` only. No touch/pointer/keyboard path: mobile and keyboard users cannot paint faces. The biggest a11y gap found.
- **Log drawer keyboard path drops focus** — `toggleLogDrawerFromKey` flips without `focusSurface`, unlike the button path. Minor.
- **Toast close unreachable** — `clientSocialSurfaces.js:94` `tabIndex=-1` + `aria-hidden`: keyboard/SR users cannot dismiss; auto-dismiss only. Minor.
- **Trade modal has no return focus** — both `openSurface("#trade-modal", "#trade-close")` calls lack `setSurfaceReturnFocus` (negotiation flow has it). Minor.
- **No skip link** — `public/index.html:1-13` has none before rails/announcer. Minor.
- **Native `alert()`** — `clientProfileBindings.js:228` breaks modal focus and styling. Trivial: replace with parlor notice.

## 3. Corrections — agent claims refuted or downgraded on re-read
- **"EXPLOIT: anon hijacks seats via restore" — refuted as novel.** The cited code is the pre-existing bearer-token path (clientId-only matching predates the reconnect work); the account check only *added* auth. Exploitation needs the victim's unguessable clientId. At most a NOTE: bearer-token design with no rate limiting.
- **"EXPLOIT: disconnected seats hijackable" — same verdict.** Same reasoning; account path additionally requires `disconnected`.
- **"New-tab-in-grace returns null" — correct behavior, not a bug.** Within 10s the old socket may still be alive; rejecting preserves one-seat-per-tab. Keep.
- **Space double-roll — refuted.** `preventDefault` on keydown suppresses button activation; server turnStage guards anyway.
- **Casino stake unclamped — refuted.** Input carries `max=maxBet`; server validates regardless.
- **`profiles[0]?.name` — refuted.** `sanitizeProfile` accepts `name` legacy; worst case a dead fallback.
- **Bank-action no-refresh — refuted.** `makeRoomVerbHandler` always emits room state; snapshot broadcast re-renders.
- **Redacted VIEW / gone-contract handling — graceful, not dead.** Missing-contract notice + picker recovery exist; worst case a UX papercut.
- **Build/sell "bypass" — overstated.** Turn + own-debt gates exist; only cross-obligation (auction/trade) overlap remains, which is strategy-adjacent. Low.
- **`restoreAccountSeat` stale timers — safe.** Dual `socketId` checks + `clearDisconnectTimer` on both ids.
- **Casino result + decline visibility — fine.** Snapshot paths cover both; ack fields are redundant, not missing.
- **Timers, persistence, parity — all NOTE-clean.** No leaks (destroyRoom clears; intervals intentional), persistence never touches GameState, zero socket orphans either direction.

# RR-20 — Client Crash/Error Observability for Release

**Audit:** Release Readiness (40-agent) · Wave 2 · Mission RR-20 · 2026-09-12
**Mode:** READ-ONLY.
**Verdict:** not a stability BLOCKER (game ships today) but a release-readiness BLOCKER for diagnosability: a silent socket/render failure mid-game is currently unfixable, and the fallback affordance is missing. Full telemetry pipeline is post-launch acceptable; items 1-4 (+10) should be the minimal pre-release patch.

Verified prior claims by grep: 0 `console.*` in production client (test files only), 0 `window.onerror`/`unhandledrejection`/`pageerror` repo-wide, 0 client-error endpoint/telemetry strings, exactly 35 bare `catch {` in `public/`, and `package.json` version `"0.0.0"`.

## Findings

1. [BLOCKER] `public/main.js:1005-1062` — entire bootstrap (`configure*`/`renderHome`/`bindEvents`/`renderAll`/`showView`) runs unguarded after all imports; any import or init throw leaves the static HTML shell with inert controls and zero feedback — friends see a dead page, you get no signal — wrap init in try/catch, report, and show reload banner; reporter must load *before* `main.js` as its own module (a failing import prevents `main.js` from ever executing).
2. [BLOCKER] `public/clientSocketListeners.js:248-251` — `applyServerState()` (`clientStateSync.js:384-431`, 30+ sequential sync steps) called bare; one throw abandons a half-applied snapshot and skips renderAll/winner/debt/auction sync (`clientStateSync.js:423-429`) — silent mid-game desync, unreproducible by report — try/catch → report + `setConnectionStatus("offline")` + re-request snapshot.
3. [BLOCKER] `public/index.html:919` + all `public/*.js` (verified absent) — no global `error`/`unhandledrejection` listeners, no console, no client→server telemetry — uncaught runtime/promise errors are invisible by construction — add `clientErrorReporter.js` module registered before `/main.js`.
4. [MAJOR] `server/server.js:69-80` — no POST route; no `express.json` body parser anywhere in `server/`; catch-all yields 404 for POST; global limiter disabled by default (`httpRateLimiter.js:50-56`, `max=0` → `next()`) — nothing can receive a report and a naive endpoint is unthrottled — add `POST /client-error` + `express.json({limit:'16kb'})` + route-scoped limiter (reuse `createHttpRateLimiter`) before static/catch-all.
5. [MAJOR] `server/telemetryModule.js:13,77-87` — only telemetry sink allowlists game-event kinds and rewrites the whole ≤5000-event file synchronously per record (known audit 7.4 stall/crash window) — reusing it for crashes adds write amplification and rejects the kind — new append-only capped crash store, reuse its `PRIVATE_KEYS`/`sanitize` pattern (`:12,28-41`) and `storeIO.writeJson` atomic temp+rename.
6. [MAJOR] `public/clientGameSave.js:76`, `public/clientSanitize.js:94,337`, `public/clientAchievements.js:94` — 4 of the 35 bare catches silently convert corrupted storage to "empty": save disappears, profile library resets, account session signs out, achievements wipe — data loss with no user notice or signal — report these four as low-severity `storage-parse` events (or toast once).
7. [MINOR] Other 31/35 bare catches are expected-environment guards: `clientSanitize` 13, `clientHomeAmbient` 3, `clientState` 3, `clientNightShift` 2, `clientPanelMenu` 2, `clientTheme` 2, `clientRoomShare` 2, `clientRoomsUi:392` 1, `main.js:225` 1 (storage denied/autoplay/clipboard; some already show "COPY FAILED") — safe to never report; wrapping these would create storm noise — leave untouched.
8. [MAJOR] `package.json:4` (`"0.0.0"`), `public/index.html:131` (hardcoded `POORUP v2.4.1`), no version meta/header — crash payload has no build identity — cannot correlate report spikes to a deploy — surface version from `package.json` at serve time into index meta and payload.
9. [MAJOR] `public/clientState.js:277` + `main.js:439` (`record()`, populated by `clientPopupUi.js:263` with `OWNED BY <name>`) and `state.messages` (chat) — capturing "last N actions" verbatim would ship aliases and chat; the only context source today carries user content — use an event-name ring buffer; never serialize messages/token/account.
10. [MINOR] `public/clientSocialSurfaces.js:29-77` — toast stack is `aria-hidden="true"` (`index.html:16`) and only server rejections reach users via `reportChatError` (`main.js:689-694`)/`parlorNotice` (`:152`); fatal client errors get no visual or SR fallback — banner must write `#error-announcer` (`index.html:15`) plus a visible Reload control.
11. [MINOR] Dedup/volume absent — no client signature/session sampler anywhere; server route limiter would default off — one render-loop throw becomes an unbounded storm once handlers exist — one report per signature/session, ~5/session cap, server daily cap + drop counter.
12. [MINOR] `qa/*.spec.js` (e.g. `qa/poorup.spec.js:1`) — no spec listens for `pageerror`; no error-injection test; traces/screenshots retain only on assertion failure (`qa/playwright.config.js:13-14`) — crash regressions ship green — shared fixture + injection spec; `ci.yml:84` already runs `test:browser`.
13. [MINOR] `README.md` / docs — no bug-report path, console instructions, or "copy diagnostics"; testers can offer only screenshots — friends-scale support is "it didn't work" — copy-diagnostics (version+room code+clientId+recent errors) + short tester doc.
14. [MINOR] Repo-wide — no privacy policy exists (only account visibility toggles, `clientAccountIdentity.js:276`); intake would collect stack/UA/IP/room code undisclosed — compliance ambiguity for public deploy — disclose fields, retention (e.g. 30 days), and IP handling before enabling endpoint.

## Minimal crash reporting patch
- `public/clientErrorReporter.js` (new): registered before main.js; `error`/`unhandledrejection` handlers with reentrancy guard, signature dedup via `sessionStorage` (≤5/session), capped payload (version, phase, roomCode, clientId, UA-trimmed, stack, boardVariant/theme, event-name action ring), `fetch`/`sendBeacon` POST, visible reload banner; exposes `window.PoorupErrors.capture()` for explicit seams.
- `public/index.html`: add `<script type="module" src="/clientErrorReporter.js"></script>` before `/main.js:919`; no CSP change (`connect-src 'self'` suffices) and no inline JS.
- `public/main.js`: wrap init block 1005-1062 in try/catch → capture + fallback; optionally capture inside existing `reportChatError`.
- `public/clientSocketListeners.js`: wrap the `applyServerState` call (248-251) and add a listener wrapper used by `configureSocketListeners`.
- `server/server.js`: `express.json({limit:'16kb'})` + `POST /client-error` before `express.static`, small per-IP `createHttpRateLimiter`, validate/sanitize, `console.error` + store.
- `server/crashReportStore.js` (new): bounded append-only NDJSON (per-day/total caps), reuse `telemetryModule` sanitize, with redaction unit tests (mirror `telemetryModule.test.js`).
- `qa/error-reporting.spec.js` (new) + shared fixture: `page.on('pageerror')`, assert one deduped/redacted POST and no PII — already covered by `test:browser`/CI.
- Docs/version: `docs/support/bug-reporting.md` (tester evidence steps) + privacy disclosure items; surface `package.json` version to client and bump it from `0.0.0`.

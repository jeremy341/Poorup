# RR-02 — Account Deletion & Data Removal Audit

**Audit:** Release Readiness (40-agent) · Wave 1 · Mission RR-02 · 2026-09-12
**Mode:** read-only
**Verdict:** BLOCKER for any GDPR-style release; MAJOR gap for a public beta with accounts. The account system is create/read/update only — no delete path exists at UI, socket, store, or HTTP layer, and no privacy/retention documentation exists. If the release does not promise erasure and accounts remain labeled beta, the minimal release-safe alternative is: (a) a documented manual-erasure runbook covering all seven stores (accounts, sessions, social, matches, achievements, seasons, cosmetics), plus a support-contact request path; or (b) disable new account registration until deletion ships. Recommended: ship item 1+2 (server deletion + session revocation) and item 10 (password-confirmed UX) before launch.

## Prior coverage check

`docs/audit/full-codebase-audit-2026-09-12.md` has **zero** deletion/erasure findings (only doc/file deletions and logout-ack `4.13`). Repo-wide grep for `delete-account|close-account|deactivate|GDPR|right to erasure`: **0 implementation matches**.

## Findings

1. [BLOCKER] `public/index.html:465` + `server/serverSocketAccount.js:118-145` — no delete-account feature exists anywhere: signed-in panel offers only EDIT ACCOUNT/SIGN OUT, the account modal (`public/clientAccountIdentity.js:286-313`) has only register/login/edit, the server registers no delete event, and there is no HTTP DELETE route — users cannot exercise erasure while `accounts.json` retains password hash/salt, 50 match records, and social graph indefinitely — ship a password-confirmed `delete-account` socket handler + UI before any release that promises privacy.
2. [MAJOR] `server/accountStore.js:430-528` — `AccountStore` has no delete/remove API; `revokeLiveSessions`/`revokePersistedSessionHashes` (`:112-122`) are module-private and `sessionTokenHash` is persisted inside the account record — a deletion cannot revoke sessions/hashes atomically, leaving stale in-memory `sessions`/`sessionHashes` entries until process restart — expose `removeAccount()` that revokes both maps, drops the record, and persists in one call.
3. [MAJOR] `server/socialStore.js:108-147,256-262` — no per-account purge: friendships, blocks, invites, reports, and the `notifications` Map keyed by accountId all survive deletion — deleted users' relationships and notification bodies (player names, match context) are retained indefinitely and remain in `social.json` — add `removeAccount(accountId)` filtering all five collections.
4. [MAJOR] `server/matchStore.js:204-213` + `server/accountStore.js:260-261` — `matches.json` keeps participant `accountId` plus contracts/market/casino detail, and every *other* participant's `matchHistory` embeds the deleted account's ID and full record — account-only deletion leaves cross-account references in other users' data — anonymize `participant.accountId` (keep `displayNameAtMatch`) in both stores.
5. [MAJOR] `server/achievementStore.js:171-196` — records keyed `${accountId}:${achievementId}`; only single-achievement `remove` exists — achievement evidence (`gameId`, `eventSequence`, `evidenceHash`) persists after account deletion — add account-wide removal or cascade it from the delete handler.
6. [MAJOR] `server/seasonModule.js:295-298,330-334,358-365` + `server/serverSocketSocial.js:187-190` — season `standings`/`claims` keyed by accountId are never purged, and missing profiles are projected as `username:'player' / displayName:'PLAYER'` — a deleted account would render as anonymous ghost rows on up to 12 seasons of leaderboards — purge standings/claims and filter orphan rows.
7. [MAJOR] `server/cosmeticCatalog.js:122-124` — `cosmetics.json` keyed by accountId (tokens, owned, equipped, claims) has no delete path — purchased/earned inventory and claim ledger survive deletion — add `removeAccount(accountId)`.
8. [MAJOR] `server/serverSocketAccount.js:351-386` + `server/accountStore.js:606-614` — behavior for deleting while seated in a live room is undefined; once the account record is gone, `recordGameResults` silently skips the seat (`getAccountById` null) and the player continues as an identity-less guest with a stale `accountId` on `socket.data` (`serverSocketAccount.js:125-126`) — deletion must force leave-room cleanup (`roomManager.leaveRoomByClient`, host reassignment) and clear `accountId` on all sockets for that account.
9. [MAJOR] `public/clientAccountIdentity.js:505-522` + `public/clientSanitize.js:329-330` — logout removes only `poorup.account.session.v1`; no flow clears the other `poorup.*` artifacts (`profiles.v1`, `profile.v1`, `save.v1`, `theme.id.v2`, sound/music/ruleset/panel, guest alias, patrol/night-shift best: `clientGameSave.js:18`, `clientThemeData.js:7`, `clientHomeAmbient.js:18`, `clientNightShift.js:25`, `clientPanelMenu.js:18`) — account-derived local data survives deletion — add a deletion reset that clears all account-derived keys and resets state.
10. [MAJOR] `public/clientSurfaces.js:235` + `public/clientProfileBindings.js:192-201` — the only destructive-confirm pattern is a generic modal used for local design deletion; there is no password re-entry, typed confirmation, or irreversibility warning for account scale — with the session token stored in localStorage (already flagged in `qa-security-premerge-2026-09-12.md:58`), a single click/XSS path could destroy an account — require current-password entry plus typed username, verified server-side.
11. [MINOR] `server/backupStore.js:39-54` — backups retain up to `DEFAULT_RETENTION=7` copies of accounts/social/matches on disk — erased data persists in backups after deletion — document retention and purge/expire backups on verified erasure requests.
12. [MINOR] `server/socketSocialApi.js:156-160` + `server/socialStore.js:149-151` — `countMutualFriends` and `areBlocked` evaluate raw persisted IDs, so stale friendship/block rows from a deleted account still affect mutual-friend counts and chat blocking (`socketSocialApi.js:285-294`) — purge rows (item 3) or resolve only live accounts.
13. [MINOR] repo docs (grep: only `docs/plans/END-TO-END-AUDIT-CS2-ROULETTE-PLAN.md`) — no privacy policy, retention statement, or erasure-contact path exists while accounts store password hashes, full match economy history, and a social graph — publish a minimal privacy notice with retention and a manual erasure request route, or ship in-app deletion (item 1).
14. [MINOR] `server/socketSocialApi.js:40-65,273-283` + `server/serverSocketAccount.js:24-27,78-101` — in-memory `socialRateBuckets`, `patrolRuns`, `authAttempts`, and `createRoomReplays` are keyed by accountId but self-expire by TTL/cap — bounded residue, no action needed beyond acknowledging account IDs exist transiently in memory.
15. [MINOR] `server/telemetryModule.js:12,28-41` — telemetry sanitizer strips account IDs (payloads are coarse event stats only) — **not** an erasure blocker; no telemetry purge is required.

## Must-fix (in order)

1 (deletion feature), 2 (atomic account/session purge), 3–7 (store purges: social, matches, achievements, seasons, cosmetics), 8 (live-room cleanup), 10 (destructive confirm UX), 9 (client key cleanup).

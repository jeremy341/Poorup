## Findings (15)

1. `[BLOCKER]` `server/server.js:124-126` + `:70-75` — No `/healthz`/`/readyz`; `app.get('*')` serves `index.html` 200 for every GET before the 404 middleware, so any probe gets HTML 200 even when stores are corrupt or the app is half-dead — external monitoring cannot distinguish up/ready; `fix`: add JSON health routes before the fallback (and before the rate limiter, or exempt them), return 503 from `/readyz` on store/backup failure.
2. `[BLOCKER]` absence (grep clean across `README.md`, `docs/`, `.github/`, `qa/`) — Nothing pings a live URL; `ci.yml:52-60` boot-smoke is build-time only; no uptime monitor, no alert channel, no deploy manifest (no Dockerfile/systemd/pm2/Procfile) — a production outage is invisible until users report it; `fix`: external uptime monitor on `/healthz` + platform restart policy; document prod URL.
3. `[MAJOR]` `server/server.js:133-139` — `uncaughtException` logs then `process.exit(1)` (piped stdout can drop the fatal line) and `unhandledRejection` only logs, suppressing Node's default crash: process keeps serving unknown/corrupt state — silent zombie or unrecorded crash; `fix`: `fs.writeSync(2, JSON line)` fatal marker with uptime/events, explicit exit policy, optional `POORUP_ALERT_WEBHOOK` POST; add SIGTERM/SIGINT shutdown log (currently absent).
4. `[MAJOR]` `server/server.js:93-102` + `server/backupStore.js:56-61` — Backup run discards per-store `results`, success is never logged, no `lastBackupAt`/age retained, and `POORUP_BACKUP_DIR` unset in production is silent — partial backup failure and stalled rotation are undetectable; `fix`: log one line per run (per-store ok/skip/bytes/duration), retain last-run state for `/readyz`, warn at boot when unset in production.
5. `[MAJOR]` `server/server.js:78`, `server/socketHandlerSupport.js:129-131`, `server/socketRuntime.js:161,169` — Raw `console.error(msg, error)` with no level/timestamp/JSON; errors lack `roomCode` (sometimes), `socketId`, `event` is present only in the wrapper, no `matchId`/`clientId` — host keyword alerting and after-the-fact triage are unreliable; `fix`: one `log(level, event, context, error)` seam (JSON single-line) used at every existing call site.
6. `[MAJOR]` `server/server.js:109`, `server/socketRuntime.js:837,711` vs `server/serverSocketAccount.js:151-153,468-483`, `server/accountStore.js:555-561`, `server/httpRateLimiter.js:33-38`, `server/socketHandlerSupport.js:110-112` — Inverted verbosity persists: connects/disconnects/GC logged `info`, while auth failures, auth/socket/http rate-limit rejections, room create/join/start, game end/settlement success, and backup success are silent — abuse and lifecycle incidents leave no trace; `fix`: log failures at `warn` (rate-limit/auth with IP or socketId, no PII), lifecycle at `info`, demote connects.
7. `[MAJOR]` absence — No counters exposed: rooms (`rooms.js:689`), sockets (`server.js:108`), games started (`serverSocketAccount.js:468`), games finished (`socketRuntime.js:173-192`), auctions, errors, persist duration (`storeIO.js:49-76`), backup runs all derivable at existing seams but nowhere accumulated — capacity/incident triage is blind; `fix`: plain in-process counter object incremented at those hooks, exposed in `/readyz` or a 60s log line (no infra).
8. `[MAJOR]` `public/` absence + `public/clientState.js:125-137,153` — Zero client error hooks (`onerror`/`unhandledrejection` absent in all 52 modules); `state.clientId` sessionStorage `poorup-client-id` and `state.roomCode` exist but are never surfaced nor sent to the server — user reports cannot be correlated to server state; `fix`: client error listener → bounded POST or "copy diagnostics" (clientId+roomCode+serverTime), add clientId to server room-event log context.
9. `[MAJOR]` `server/storeIO.js:15-36` + all store constructors (`accountStore.js:440`, `matchStore.js:195`, `socialStore.js:120`, `achievementStore.js:162`, `seasonModule.js:290`, `cosmeticCatalog.js:114`, `telemetryModule.js:69`) — `{missing, corrupt}` load flags are discarded and `writeJson` records no timestamps — `/readyz` cannot report which store is quarantined/stale; corruption is visible only as one startup line + `.corrupt-*` file; `fix`: retain load state per store and last persist time/ok in `writeJson`.

15. `[MINOR]` `README.md` (localhost only) + absence — Production URL/host, env template (`.env.example` still missing), and monitoring references are absent — monitoring, alert routing, and support triage cannot be wired from the repo; `fix`: document deploy target, health URLs, and alert keywords.

## Health/readiness design (what this app should report)

- `GET /healthz` (liveness, no auth, `Cache-Control: no-store`, before `app.get('*')`): `{status:"ok", uptimeSec, version, commit, node, pid, rssMB}` — 200 while the event loop responds.
- `GET /readyz` (readiness, 503 on failure): `{status, version, rooms: roomManager.rooms.size, sockets: io.engine.clientsCount, memory:{rss,heapUsed}, stores:{<name>:{loaded|missing|corrupt, lastPersistAt}}, backups:{lastAt, ageSec, lastOk, storesOk}}`. Data needed: retain `loadJson` flags (finding 9), last write time in `writeJson`, last backup result in `runBackup` (finding 4). Keep body count-only (no PII); optional `POORUP_HEALTH_TOKEN` for detail. Note a monitor must key on status/body, since the SPA fallback returns HTML 200 for everything today.

# Poorup UX Audit — Reset Slice — 2026-09-11

## Scope

This is the 1920×1080-focused audit for the reset and social/lobby slice. It
keeps the original Poorup layout, fonts, rails, board, modal stack, and
interaction vocabulary. It does not redesign the game shell or change rules.

## Confirmed issues and decisions

| Priority | Surface | Finding | Decision |
| --- | --- | --- | --- |
| High | Public lobby | Local `buildPlayers` and lobby rendering could show demo CPU seats before the server acknowledged a room. | Show only the acknowledged human seat in setup/lobby; create bots only in `Room.startGame()`. |
| High | Game topbar | `FOCUS` duplicated panel visibility and left a second focus state in CSS/JS. | Remove the button, listener, and dead focus styles. Keep reversible rail controls in `PANELS`. |
| High | Social guest modal | A guest saw an account note inside the feed while the rest of the surface remained actionable. | Add an account gate, blur and inert the underlying content, keep `CREATE ACCOUNT`, Close, Escape, and Scrim usable. |
| Medium | Social search | The FIND button aligned to the label/help block bottom instead of the input. | Use a dedicated search row; input and button are both 44px and align at the top of the row. |
| Medium | Social modal sizing | The 720px cap made the three-column context cramped at desktop width. | Use the same surface stack with a measured maximum of `min(1080px, 100vw - 48px)` and an internal 88vh ceiling. |

## Root-cause notes

- The server-side `RoomManager.createRoom()` already assigns the creator as
  `hostId` and `isHost`, and `ensureBots()` runs from `Room.startGame()`. The
  visible pre-start bots were client placeholders, not server seats.
- Create requests now carry a bounded opaque `requestId`; the server returns
  `created`, `hostId`, `playerId`, `bots`, and the same request id, and replays
  a duplicate create without creating another table.
- `clientStateSync.serverPlayerView()` already carries `isHost`; the reset
  slice does not change that contract. New lifecycle tests prove creator host
  ownership and zero bots at creation.
- Social guest content is marked `aria-hidden` and `inert` while the gate is
  shown. This prevents the blur from being mistaken for a privacy boundary.

## 1920×1080 inspection checklist

- [ ] Home status strip does not shift when room counts resolve.
- [ ] Room browse/create/join controls share a baseline and retain 44px targets.
- [ ] Public room creation displays one human seat and a clear host state.
- [ ] Lobby settings show reserved bot count without rendering fake players.
- [ ] Game topbar no longer contains FOCUS; PANELS remains reachable.
- [ ] Social guest gate stays centered and does not cover the close control.
- [ ] Social input and FIND button are exactly 44px tall.
- [ ] Social modal body scrolls internally; document never scrolls.
- [ ] Social search results, empty, error, and loading states do not move the
  input row.
- [ ] Profile, Rankings, Rules, Market, Casino, Trade, Loan, Card, and Log
  surfaces retain their existing widths and focus restoration.

## Accessibility gates

- Native buttons and form controls remain the interaction surface.
- Guest content is inert rather than merely visually blurred.
- Gate and errors are announced through existing live-region patterns.
- Focus returns to the opener after modal dismissal.
- Keyboard navigation, 200% zoom, Reduced Motion, Forced Colors, and touch
  targets are part of the browser run.

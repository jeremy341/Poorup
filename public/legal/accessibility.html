Accessibility statement

How the parlor supports keyboard, touch, screen-reader, contrast, motion, and text-zoom needs.

1. Target and scope

This statement covers the Poorup website, public documents, room flows, profile surfaces, rankings, social surfaces, and the game board. The operator must confirm the intended WCAG version, conformance target, supported browsers, and audit date for the effective release.

2. Keyboard and focus

Important actions use native buttons, links, inputs, and selects. Skip links move to the page main, focus is visible, modal focus returns to its opener, and document anchors use stable headings. Decorative scenery and pixel art never take focus.

3. Screen readers and semantics

Pages use one primary heading, ordered section headings, labelled regions, polite live updates for changing game status, and text alternatives for meaningful images. Decorative art is hidden from assistive technology. The final audit must verify the exact supported screen readers and browser combinations.

4. Contrast and colour

Text, borders, status colours, and focus indicators are tested against the Poorup dark surfaces. Colour is not the only cue for an actionable state. Forced-colors mode keeps controls and focus visible with system colours.

5. Motion and flashing

Ambient scenes and transitions use restrained transform and opacity motion. Reduced-motion preferences pause decorative movement and remove nonessential transitions. No game result depends on animation timing. The effective statement will record any remaining motion limitation.

6. Responsive and zoom behavior

The primary tablet layout is landscape. The interface is also tested at desktop, narrow tablet, and phone widths, with 200% text zoom and touch targets of at least 44px where appropriate. Legal documents remain readable without horizontal page scrolling.

7. Feedback and limitations

Tell Support which page, device, browser, input method, or assistive technology caused difficulty. Include a screenshot only when it contains no private data. The operator must publish the accessibility contact, response target, and alternative access route before this statement becomes effective.

PROVENANCE CHECK. A filename or package name is not a license. The effective page must link to the exact license and preserve required notices.

1. Runtime assets

Poorup loads local fonts, interface artwork, board graphics, theme scenes, icons, and audio from the public asset tree. Each asset family needs an owner, source URL or creation record, license, version, and attribution requirement before release.

2. Open-source code

The service uses open-source runtime and development packages. The effective notice will include a generated dependency inventory, package versions, license identifiers, and the full notices required by those licenses. This page does not replace the license terms of a dependency.

4. Art, SVGs, and pixel scenes

Poorup-authored SVGs and pixel art should be marked as original work by the operator or credited creator. Third-party references, generated assets, and commissioned work need separate permission records. Do not ship artwork copied from a game, brand, or screenshot without a documented license.

5. Attribution and notices

When a license requires attribution, the effective page will reproduce the required notice in an accessible form and link to the source. If an asset has no confirmed license, it will be removed, replaced, or kept out of the release rather than silently marked as free.

6. License questions

Send a provenance question through the Support notice before redistributing a Poorup asset. Include the asset path and release version, not a private credential or session token. The operator must publish the final contact channel and response policy.
